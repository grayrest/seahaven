# flatland: the platform

D10, D17–D19, D25, D43 and D45, and the thing this repository has been building
toward without yet naming as a milestone. Everything so far confines a *shell*.
Nothing yet lets Roc code run inside that confinement, which is the point of the
project: flatland is meant to replace `basic-cli` as `~/dev/roc/rocjust`'s
platform, and the shell surface is the means.

## What is actually this repository's

rocjust is two halves and only one of them is a client of this work. `just/` is
a Roc **package** — lexer, parser, analyzer, evaluator, all pure, no platform,
no effects — and it needs nothing from here at all. `app/` is the CLI, and it is
where every effect the port performs lives. That is the surface this milestone
implements.

Stated up front so the milestone is not read as delivering more than it does:
**the wasm tier is not in it, and neither is the parallel scheduler.** D17 makes
wasm the default tier and native the trusted opt-in; this builds the native
binding first, for the reasons under "The change", and D18's whole argument is
that doing so does not fork the API. D25's `spawn`/`wait_any` is in the ABI and
its scheduler is not.

## The surface, measured

From `app/*.roc`, by call site rather than by reading the platform's exports:
**54 distinct calls across 11 modules.**

| Module | Distinct | Sites | Where the answer already lives |
| --- | --- | --- | --- |
| `Path` | 19 | 124 | `brush-vfs` (D6, D10, D45) |
| `Stdout`/`Stderr`/`Stdin` | 6 | 58 | D20, D28 |
| `Env` | 10 | 35 | D21, D15, D30 |
| `Cmd` | 8 | 27 | D2, D24, D25, D30 |
| `OsStr` | 4 | 27 | D45 |
| `Signal` | 3 | 9 | **nothing** |
| `Regex` | 2 | 5 | already in the binary |
| `IOErr` | 1 | 3 | — |
| `Tty` | 1 | 2 | D36 |
| | **54** | **290** | |

That reaches about **30 of basic-cli's 72 hosted effects**. The other 42 are not
deferred work: `http_*` and `tcp_*` are gone by D9, which makes the shell
permanently network-free, and `sqlite_*`, `random_*`, `sleep_*`, `utc_*`,
`locale_*` and the `Url` surface are simply not called by rocjust. A platform
that implements what its one consumer uses is the whole deliverable; the rest
is scope that has never justified itself.

**`Path.utf8` alone is 44 of those 290 sites — the single most-used call in the
whole surface — and that matters more than it looks.** basic-cli's `NativePath`
is `[Utf8(Str), UnixBytes(List(U8)), WindowsU16s(List(U16))]`, the union D45
rejected. The port collapses it to the
first variant, and the measured call sites say that is not a concession: the app
already builds paths from strings almost everywhere.

## What is already true

- **The filesystem half is nearly a one-for-one map.** `read_utf8!` →
  `Vfs::open`, `list!` → `Vfs::read_dir_names`, `canonicalize!` →
  `Vfs::canonicalize`, and so on across `Path`'s nineteen. This is the part four
  milestones of work were for.
- **The host to port is the same shape of problem D4 already solved.**
  basic-cli's host is a `staticlib` of `#[no_mangle] pub extern "C" fn hosted_*`
  functions whose bodies call `std::fs` directly —
  `hosted_dir_create` is literally `fs::create_dir(path)`. That is the codemod
  target D34 describes, and `check ban` (195 entries, all firing) is the gate
  that proves it landed. The lint that has been guarding the forks guards this
  crate the day it exists.
- **The env questions are answered and the answers are not "inherit".** D21's
  three classes cover `var!`/`dict!`/`temp_dir!`; D15 makes `cwd!`/`set_cwd!` a
  session fact rather than a process one; D30 makes `exe_path!` return
  `/bin/just`.
- **D36 answers `Tty.is_terminal!` outright** — the constant `false`, no
  mechanism needed.
- **A regex engine is already linked in.** The bundled utilities pull `onig`
  through `uu_grep`, `uu_expr` and `findutils`, and brush compiles globs with
  `fancy_regex`. `regex_is_match!` and `regex_replace_all!` need no new
  dependency and no host reach.
- **Nothing covers signals.** rocjust calls `install!`, `take!` and `name`, and
  the decision log has no entry. That is a decision this milestone makes, not a
  mechanism it wires up.

## The change

**Step 0 — the effect list is one Rust trait, written before either binding.**
D18's claim is that one Roc API binds as wasm imports in one tier and direct
calls in the other, "no drift". A claim like that is worth nothing as prose and
everything as a type: the effects are a trait, the native `hosted_*` exports are
one implementation, and the wasm `Linker` is the other when it arrives. D19's
"identical capability" then holds because the compiler enforces it rather than
because someone remembered.

**Step 1 — the filesystem effects, routed through the facade.** `Path`'s
nineteen calls, mechanically. The only one with a decision inside it is `list!`,
where D45's skip already applies and the Roc side inherits it for free.
`path_type!` maps to `symlink_metadata` rather than `metadata`, because a
`SymLink` variant that never appears is a lie the type system will not catch.

**Step 2 — env, and it is where the leaks would be.** D21's classes decide
`var!` and `dict!`. `temp_dir!` is synthesized, not read. `exe_path!` is
`/bin/just` per D30. `cwd!`/`set_cwd!` read and write the *session's* directory,
which is the first consumer D15 has had outside the shell itself.

`platform!` reports the **real** host OS, and that is deliberate rather than an
oversight: justfiles carry `[macos]`/`[linux]`/`[windows]` attributes and
rocjust must evaluate them the way upstream does. It is a fact about the machine
that the guest can already infer from a hundred other places, and refusing it
would break the feature it exists for.

`pid!` and `num_cpus!` are the two with no answer yet. `pid!` must not be the
host's — see the risk section.

**Step 3 — stdio, subject to D28.** Six calls, 58 sites, and by far the most
used part of the surface. Output is per-job buffered, which the guest does not
see and must not be able to defeat.

**Step 4 — `Cmd` is `spawn` + `wait_any` in the ABI and blocking underneath.**
D25 says a blocking exec serializes everything and warns that retrofitting
handles means re-porting the Roc app. So the shape lands now — `spawn!` returns
a job handle, `wait_any!` takes a list — and the first implementation waits
immediately, so behaviour is identical to today and rocjust's four `exec_*` call
sites port unchanged. The scheduler is a later milestone; the ABI is not.

Execution itself is D2's predicate, D24's broker and D30's trampoline, all of
which exist.

**Step 5 — signals are a synthesized queue, and the host's are not forwarded.**
`install!` arms a queue the *sandbox* feeds — job completion, D35's deadline,
the launcher asking for shutdown — and `take!` returns 0 in an ordinary run.
D36 already removed the terminal, so `SIGWINCH` and `SIGTSTP` have nothing to
mean; forwarding `SIGINT` would put a host-controlled event across the boundary
and needs its own argument about what a hostile guest does with the knowledge.
This is recorded as a decision with a cost, not as a gap: rocjust's `signals::`
score stays where it is.

**Step 6 — the small ones.** `regex_*` against the linked engine, `tty_*` as
D36's constant, `IOErr` mapping. None carries a decision.

**Step 7 — link it and run rocjust against it.** The milestone is not the crate,
it is rocjust's `app/main.roc` building on this platform and its differential
harness running. Anything short of that has not been shown to work.

## Gates

1. **`check ban` sees the new crate**, and fails on a `std::fs` call added to
   it. Asserted by adding one and watching it fail, not by reading the config —
   the ban has 195 entries and a crate outside its globs is silently exempt.
2. **Every one of the 54 measured call sites resolves.** Not "the crate
   compiles": the app does.
3. **A path outside the grant is unnameable from Roc**, through the same four
   routes the shell is tested on. D10 says confinement comes from the mount
   table regardless of the API's shape, and this is where that gets checked
   rather than asserted.
4. **`cwd!` answers the session's directory, not the process's**, and
   `set_cwd!` does not move the process. The bug this catches is the one D15
   exists for, and it is invisible until two sessions differ.
5. **The `spawn`/`wait_any` shape survives its blocking implementation** — a
   test that holds two handles at once and waits on both, which passes under a
   serial implementation and would fail under an ABI that cannot express it.
6. **The env classes hold at the boundary**: a denied variable is absent from
   `dict!`, not merely absent from `var!`. Two calls, one policy.
7. **The differential**: rocjust's own harness, run against this platform and
   against basic-cli, compared. It is at 1192 cases with 0 failing today, so a
   difference is a real signal rather than noise.
8. **Not vacuous**: the differential must be shown to *notice* — one deliberate
   divergence, asserted to fail, in the shape `confinement_is_invisible` already
   uses.

## Risk

**The native tier puts the Roc compiler in the TCB, and this milestone ships
only that tier.** D17 says so plainly and rocjust documents a live miscompile on
the current toolchain. So the platform this produces is for **trusted code**,
and the trust store (D29, D19) has to record the tier rather than let it
default. Getting this wrong is not a bug that shows up in a test; it is a
milestone that looks finished and is not.

**The Roc toolchain is a new build axis.** `roc` is not a Cargo dependency, the
host links as a `staticlib`, and CI currently knows nothing about either. A gate
that cannot run in CI is a gate that rots — D13's whole argument about
`check forks`, and the same trap that let a re-vendor silently revert three
routing patches.

**`pid!` is a small hole with a large shape.** rocjust calls it twice and
upstream's `signals::` tests want a *child's* pid. Returning the host's process
id leaks a host fact into the namespace for no benefit; returning a synthetic
one means the number is not usable for anything a pid is usually for. It needs
an answer before step 2 rather than after.

**The differential is the only end-to-end gate, and its corpus is hand-written.**
rocjust's own `DIVERGENCES.md` says this about itself: 1192 cases and 0 failures
"proves the port matches on the paths the corpus exercises, and the corpus is
hand-written, so it cannot find what it never calls."

## What stays behind

The wasm tier (D17, D18's other binding), the parallel scheduler (D25's
executor, and with it `parallel::` and the child pid `signals::` wants), D35's
deadlines and memory budgets, D43's per-frame handle tables, and D16's grant
derivation from the justfile graph — which is rocjust's, not this repository's,
and was scoped out of the launcher milestone for the same reason.
