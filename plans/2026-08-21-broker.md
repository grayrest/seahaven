# seahaven: carry the session to the child

D24. Every policy this tree has built governs the shell's own process. A bundled
utility does not run there — it runs in a fresh process the shell re-execs (D5),
and nothing crosses that boundary except argv, the environment, and file
descriptors. So the namespace does not reach it.

**Status: implemented on Unix, compile-checked only on Windows.** See "Where it
landed" at the end.

## The hole, measured

With every confinement flag this tree has switched on at once:

```
$ brush --mount /work:$PWD/jail:rw --closed-world --restrict-builtins \
        -c 'cat /etc/hosts'
##
# Host Database
$ ... -c 'ls /etc | wc -l'
82
$ ... -c 'cat /work/inside.txt'
cat: /work/inside.txt: No such file or directory
```

Three symptoms of one cause. The child was handed no policy, so
`install_dispatch_session` (`brush-shell/src/bundled.rs:175`) gives it the
*identity* namespace — the host filesystem — and it reads and enumerates freely.
The third line is the same fact wearing the opposite face: a virtual path the
parent understands means nothing to a child resolving against the host.

None of this is a regression. D2's entry records it, and the seam carries a
comment naming this milestone. It is stated here because the configuration built
to make the confinement claim true is the configuration in which it is false.

## What is already true

Measured or read, not assumed. Most of it makes the milestone smaller than D24's
framing suggests.

- **The seam exists and is signposted.** `install_dispatch_session` is one
  function, called from one place, whose entire job is to choose the child's
  namespace. It currently chooses identity.
- **Redirections already cross, and correctly.** `inject_fds`
  (`sys/unix/commands.rs`) hands the child its fds; under
  `--mount ... --closed-world`, both `cat inside.txt > copied.txt` and
  `exec 3>fd3.txt` land inside the mount. So the broker does **not** need to
  carry stdio, which is the part of D24 that reads hardest.
- **The cwd already crosses — as a host path.** `commands.rs:229` does
  `cmd.current_dir(host_cwd)`, which is exactly why relative paths work and
  absolute virtual ones do not. D15 says that line must be **deleted**, not
  adapted; it cannot be until the child has a namespace to resolve against.
- **What must actually cross is small.** `Session` is `{ vfs: Arc<Vfs>, cwd:
  VirtualPath }`, and a `Vfs` is a `MountTable`. Per mount: a virtual mount
  point, an `Access`, and a `Dir`. Nothing else. A bundled child runs one
  utility — it needs a namespace and a cwd, not a `Shell`.
- **`Mount::dir()` is deliberately crate-private**, documented as "a `Dir` is the
  authority itself, and the facade's whole contract is that callers receive
  paths and descriptors rather than capabilities they could re-root from".
  Passing handles needs a second narrow D3 amendment, named and scoped the way
  `Dir::into_owned_fd_for_at_traversal` was.
- **The ban already forbids the primitives this needs.** `clippy.toml:164-168`
  disallows `UnixListener::bind` ("creates a host file outside every mount"),
  `UnixStream::connect` and `SocketAddr::from_pathname` ("a socket address is a
  host path"). That is not an obstacle to route around — it is the ban correctly
  describing what a rendezvous socket *is*, and this milestone has to answer it
  with a scoped exemption rather than a deletion. `cargo xtask check ban` lints a
  fixture that must trigger every entry, so an exemption at the call site leaves
  the ban intact.
- **The no-exec invariant is load-bearing, and holds.** `--inherit-fd`
  (`entry.rs:609-613`) turns any integer into a dup'd fd, and the shim never puts
  it on a child's argv. Forgery is impossible only because a script under a
  closed world cannot spawn anything at all.
- **There is no IPC anywhere in the tree.** D9 records zero network code; there
  is also no socket or pipe code of any kind. This milestone writes the first.
- **D24's serde correction is half stale.** `null()` is now a process-lifetime
  handle preopened during shell construction (`openfiles.rs:98-123`), with a
  comment about exactly this hazard, so it is no longer opened by host path after
  the sandbox closes. What still stands is that `OpenFile::deserialize` turns
  every non-stdio variant into it. That does not bite here, because the bundled
  child needs no serde blob — but it will the first time a real sub-shell has to
  cross, and the entry should say so rather than read as fixed.
- **Windows children get stdio and nothing else.** `command-fds` is
  `cfg(unix)`, and `sys/stubs/commands.rs:72` errors on any fd to inject. So on
  Windows even `3>file` fails today, before this milestone adds anything.

## The change

**Step 0 — a way to lend a mount's handle.** The second D3 amendment. Scoped
like the first: one method, named for its single caller, documented with why the
capability may leave the facade here and nowhere else. It lends the handle to a
*child of this process under this shell's own policy* — not to sandboxed code.

**Step 1 — the rendezvous.** A unix socket or named pipe in a `0700` directory,
with the scoped ban exemption from above. D32's correction applies: creating and
then validating that directory is itself a TOCTOU check on macOS, where there is
no `openat2`, so the rendezvous rests on cap-std's weaker implementation and the
plan should not claim otherwise.

**Step 2 — the handshake, and the credential is the pid.** macOS gives pid *xor*
uid, and this design takes the **pid**: `LOCAL_PEERPID` on macOS, `SO_PEERCRED`
on Linux, `GetNamedPipeClientProcessId` on Windows. One question, one answer,
three platforms — the alternative, `LOCAL_PEERCRED`, yields a uid on macOS and
would leave the design checking different things depending on where it runs.

**The consequence has to be stated rather than buried: with pid as the
credential, nothing in the handshake checks uid**, so cross-user isolation rests
entirely on the rendezvous directory's `0700` mode (a user-SID DACL on Windows).
D32 already names that as the cross-user mechanism; what changes is that it is
now the *only* one, not a second layer.

Peer credentials bind a *connection*, not a session, so the parent must know the
child's pid before it can validate anything. The order is: create the listener,
spawn (which yields the pid), *then* accept — the child blocks in `connect`
until the parent is ready, and no connection is ever validated against an
unknown pid. Acceptance is **one-shot**: a double-connect passes the credential
check identically, and fd passing has no revocation.

**The rendezvous path travels in the environment, not in argv.** D32 rejected a
nonce in argv because `/proc/PID/cmdline` is world-readable; `/proc/PID/environ`
is not. It also keeps `argv[2]` as the dispatched utility name, which D11's
predicate reads.

**Step 3 — the child builds its namespace from what it received** and installs
it at `install_dispatch_session`'s seam instead of identity. A child that cannot
complete the handshake must fail closed — no session, every filesystem call
refused — never fall back to identity, which is the bug this milestone exists to
remove.

**Step 4 — delete `cmd.current_dir(host_cwd)`** (D15) and send the virtual cwd
across instead. This is what makes `cat /work/inside.txt` work, and it cannot
happen before step 3.

**Step 5 — Windows, in this milestone.** A named pipe replaces the socket,
`GetNamedPipeClientProcessId` replaces the peer-credential call, and
`DuplicateHandle` replaces `SCM_RIGHTS` — which inverts the mechanism rather
than mirroring it: on Unix the descriptors ride in the control message, while on
Windows the parent duplicates each handle *into the child's process* and sends
the resulting numeric values in the payload. So the parent needs the child's
process handle, which it has, and the child receives integers it must not
validate — a handle value it did not receive by duplication is not a handle it
can use.

**What this milestone cannot do is run the Windows path.** It is developed on
macOS, so Windows gets compile coverage through `cargo xtask check build`'s
cross target and its correctness rests on review, not execution. That is a
weaker claim than the Unix half and the milestone says so rather than reporting
one number for both.

## Gates

1. **The three measured transcripts, inverted.** `cat /etc/hosts` refused, `ls
   /etc` enumerating nothing, `cat /work/inside.txt` succeeding. The third is
   not a bonus — it is the proof the namespace *arrived* rather than the child
   merely being crippled.
2. **A child that fails the handshake reaches nothing**, and is distinguishable
   from one that was never confined. Assert the refusal, not just a non-zero
   exit.
3. **The ordering race.** Registration before spawn, asserted by a test that
   would pass either way if the order were reversed only under load — so it has
   to force the interleaving rather than hope for it.
4. **A second connection on the same rendezvous is refused**, since fd passing
   cannot be taken back.
5. **Not vacuous.** The mounts the child ends up with must be compared against
   the parent's, not merely counted; a child with an empty namespace passes
   every "cannot reach the host" assertion for the wrong reason.
6. **The compat suite is unaffected**, since under identity the parent hands the
   child the host anyway. D8's shape.
7. **Handshake cost is measured, not assumed.** A recipe runs bundled commands
   constantly and this adds a round trip to each one. A number belongs in the
   milestone even if it is a small one — the walker's performance gate was
   dropped and no number was claimed, which is a gap worth not repeating.

## Risk

**This writes the first IPC in the tree, and D9 says the shell is permanently
network-free.** A unix socket is not network reachability, but the claim should
be restated to say so explicitly rather than quietly narrowed by a milestone
that contradicts its plain reading.

**Windows is written blind.** Compile-checked, not run. The named-pipe and
`DuplicateHandle` paths are the half of this milestone most likely to be wrong,
and nothing in this repository will catch it before someone runs it there.

**The rendezvous is the new attack surface, and it is a host path.** The ban
entries this milestone exempts are correct about what a socket is; the exemption
has to be as narrow as the ones D38 and the launcher's own `File::open` carry,
or the ban becomes a thing readers assume is exempted somewhere.

**Failing open is the easy mistake.** Every step has a natural fallback to
identity — that is what the code does today — and each one silently restores the
hole this milestone closes.

## What stays behind

D25's `spawn`/`wait_any` and D43's per-frame handle tables, both of which want
this handshake but are their own designs. The serde blob, which a bundled child
does not need and a crossing sub-shell will. D16's grant derivation, which
decides *what* a session contains rather than how it travels.

## Where it landed

Written after the fact. The plan above is left as written so the difference is
visible.

### Built as planned

Steps 0–5 and gates 1–7. The three measured transcripts are inverted, including
the third: `cat /work/inside.txt` now works, which is the one that proves the
namespace *arrived* rather than the child being crippled. `lend_to_child` is the
second D3 amendment; the rendezvous is a `0700` directory on Unix and an
owner-only SDDL on Windows; the credential is the pid on all three platforms;
acceptance is one-shot; `cmd.current_dir(host_cwd)` still runs but the child no
longer depends on it, and D15's deletion is what "not built" records below.

### Built differently

**The rendezvous is created in `compose_std_command`, not beside it.** Putting
it anywhere else would have meant recomputing "is this a bundled dispatch",
which is D2's predicate — and a second copy of a predicate is how the two drift.
So the function returns `(Command, Option<Rendezvous>)` and the spawn site
serves it once the child has a pid.

**`exec` of a bundled dispatch is now refused.** It is the case the ordering
cannot serve: `exec` leaves no parent, so the child would wait out its timeout
and fail closed — a correct answer delivered as a ten-second hang. A
`Disposition` parameter distinguishes the two callers, and D11's decision to
*allow* `exec` is unaffected: its redirection form is untouched.

**The credential check is not the only thing the ordering buys.** The plan
framed accept-after-spawn as satisfying D32. It also means a child that dies
before `main` cannot wedge the parent, because the accept has a deadline — which
the plan did not think to require and the first implementation got wrong in the
other direction, retrying a `connect` to a path that did not exist until the
full ten seconds elapsed.

### Built after the fact

**Two `Path::is_dir` calls in `uu_grep`, routed by hand.** They are inherent
methods, so D34 puts them outside the codemod, and they asked the host. Nothing
noticed until a child had a real namespace to be wrong about: before D24 the
child ran under identity, where a virtual path did not resolve either, so the
bug and the missing broker produced the same message. Recorded in
`forks/RESIDUAL-PATCHES.md`.

**A read-only mount is asserted to stay read-only in the child.** Access is one
byte on the wire and is the thing most likely to be dropped silently, which
would turn every mount writable on the far side of the handshake.

### Measured

Gate 7, which the walker's equivalent was dropped without a number. 200 bundled
dispatches, debug build, medians of seven runs: **1.760s without the handshake,
2.040s with it — about 1.4 ms per dispatch** on top of ~8.8 ms of process spawn.
The handshake is syscall-bound where the spawn is not, so the *ratio* will look
worse in a release build even though the absolute cost will not move much.

### Not built

**~~`cmd.current_dir(host_cwd)` was not deleted.~~** Done afterwards, as D15's
own step. It is deleted for the bundled dispatch only: deleting it for every
external command was measured and costs `cd /tmp && /bin/pwd` and 7
compatibility cases, because a host program has no session to carry a cwd. See
D15 in the decision log.

**The Windows path has never been run.** It is compile-checked through
`cargo xtask check build`'s cross target and nothing more. Every number and
every gate in this milestone is a Unix number and a Unix gate.

**Nothing else crosses.** Env, stdio beyond the fds `inject_fds` already
carries, clock, RNG and locale are all D15 session facts that this handshake
could carry and does not.

**The execution policy is on that list too, and it has already cost something.**
`SessionPayload` is `cwd` and `mounts`; D2's closed world is a *parent-side*
predicate, so a bundled utility has no policy object to consult and no way to
learn one exists. `findutils` spawned children with `std::process::Command`, and
measured, `/bin/echo` was refused directly with exit 127 and ran fine through
`find . -exec /bin/echo` — arbitrary host execution from inside a closed world.
That capability is dropped rather than fixed, per D4, and the fix is here:

- **Follow-up: carry the execution policy, and give a bundled utility a bounded
  `-exec` against it.** The shape is the same as the namespace's — a session
  fact the handshake hands over — and it generalises, because any bundled
  utility that spawns has this hole; `find` is only the one that ships with the
  feature. What it buys is `-exec` in the *open* world, where running a host
  binary is legitimate and bash's `find` does it. Under a closed world a routed
  `-exec` refuses, which is what dropping it already achieves, so the value is
  entirely in the open-world case.
- **`-execdir` and `-okdir` cannot be routed, even then.** They `chdir` to each
  file's parent before spawning, and a host program has no session and so cannot
  take a virtual working directory. That is the same reason `cmd.current_dir` was
  deleted for bundled dispatch and kept for external commands — see D15. A
  bounded `-exec` therefore means `-exec` only, and the `dir` variants stay
  dropped.
- **Not a conditional refusal.** Having `find` ask "am I sandboxed?" and behave
  differently is the shape the builtin-allowlist milestone already records as
  knowingly wrong (`is_open()` is the wrong question). The policy object is the
  answer; until it crosses, refusing unconditionally is the honest stand-in.
