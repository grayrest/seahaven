# D13's rule: a case that starts *passing* is itself a failure, so an entry
# whose cause is fixed must be removed rather than left to rot.

# macOS only. `%y` on a unix socket reports `U` (unknown) instead of `s`.
#
# brush-vfs's `symlink_metadata` opens the entry and `fstat`s the descriptor,
# because `std::fs::Metadata` has no public constructor and `fstatat` therefore
# cannot produce one. macOS refuses to `open` a socket at all, so the stat
# fails and `find` falls back to `U`. Linux is unaffected: `O_PATH` does not
# really open the file, and this test passes there.
#
# Fails closed -- an error about something *inside* the namespace, not a wrong
# answer about something outside it. See the note on `symlink_metadata_at`.
find::matchers::printf::tests::test_printf_special_types

# FLATLAND DIVERGENCE, not an upstream failure. `-exec`, `-execdir`, `-ok` and
# `-okdir` are dropped: they spawned a child with `std::process::Command`, which
# goes around D2's closed world entirely -- `/bin/echo` is refused directly with
# exit 127 and runs fine through `find . -exec /bin/echo` -- and `-execdir`
# additionally ran the child in the *host's* working directory.
#
# These four assert that the predicates *parse into a matcher*, which is exactly
# the capability that was removed, so they fail by construction rather than by
# accident. D13 asks that a divergence entry name the decision behind it: D4's
# disposition, "drop the capability and keep the utility". Routing `-exec`
# instead is recorded as a follow-up in plans/2026-08-21-broker.md.
